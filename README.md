# متجر بيعلي جملة

منصة طلب إلكترونية عربية لعرض وبيع الأدوات المدرسية والمكتبية لسكان توشكى. يعمل المتجر كواجهة ويب خفيفة بدون إطار عمل، ويحمّل المنتجات من ملف JSON، ثم يرسل تفاصيل الطلب إلى إدارة المتجر عبر Telegram من خلال دالة خلفية آمنة.

## نظرة عامة

يوفر الموقع تجربة شراء بسيطة ومتجاوبة باللغة العربية ومن اليمين إلى اليسار. يستطيع العميل:

1. تصفح المنتجات حسب القسم أو عرض جميع الأقسام.
2. فتح صورة المنتج بحجم أكبر.
3. زيادة الكمية أو إنقاصها مع احترام الحد الأقصى لكل منتج.
4. مراجعة ملخص الطلب ومجموع المنتجات ورسوم التوصيل.
5. إدخال بيانات التوصيل وإرسال الطلب.
6. استلام رقم طلب بعد نجاح الإرسال.

الطلبات لا تُحفظ في قاعدة بيانات؛ بل تُرسل رسالة منسقة إلى محادثة Telegram المحددة في إعدادات الخادم.

## المزايا

- واجهة RTL عربية ومتوافقة مع شاشات الهاتف والحاسوب.
- 70 منتجًا حاليًا موزعة على الأقسام التالية:
  - أدوات الرسم
  - أقلام وأدوات مكتبية
  - كشاكيل وكراسات
  - لانشبوك وزمزمية
  - مقالم وشنط
- سعر التوصيل الثابت: **5 جنيه مصري**.
- الدفع عند الاستلام نقدًا.
- تحقق من رقم الهاتف المصري بصيغة 11 رقمًا تبدأ بـ `010` أو `011` أو `012` أو `015`.
- حد أقصى مستقل للكمية لكل منتج.
- رسائل نجاح وخطأ، نافذة نجاح تحتوي على رقم الطلب، وخريطة للموقع.
- روابط مباشرة إلى WhatsApp وFacebook.
- مفتاح Telegram غير مكشوف في كود الواجهة.

## التقنيات المستخدمة

- HTML5 وJavaScript بدون إطار عمل.
- Tailwind CSS عبر CDN.
- Font Awesome عبر CDN.
- Google Font: Tajawal.
- Vercel Serverless Functions لمعالجة إرسال الطلب.
- Telegram Bot API لإشعارات الطلبات.
- صور المنتجات بصيغة WebP، والشعار بصيغة AVIF.

## متطلبات التشغيل

- متصفح حديث يدعم JavaScript و`fetch`.
- لتشغيل الواجهة فقط: خادم ملفات ثابت.
- لإرسال الطلبات محليًا: Node.js وnpm وVercel CLI.
- حساب Vercel للنشر.
- Telegram Bot و`chat ID` لاستقبال الطلبات.

## تشغيل المشروع محليًا

### معاينة الواجهة فقط

لا تفتح `index.html` مباشرة من نظام الملفات؛ لأن تحميل `products.json` عبر `fetch` قد يُمنع بسبب سياسة المتصفح. شغّل خادم ملفات ثابتًا من مجلد المشروع، مثلًا:

```bash
npx serve .
```

ثم افتح الرابط الذي يظهر في الطرفية. هذه الطريقة تعرض المنتجات، لكنها لا توفر دالة `/api/send-telegram` ما لم تُشغّل بيئة Vercel.

### تشغيل الواجهة مع API

ثبّت Vercel CLI مرة واحدة:

```bash
npm install --global vercel
```

من داخل مجلد المشروع، أنشئ ملفًا اسمه `.env` وضع فيه:

```env
TELEGRAM_BOT_TOKEN=ضع_توكن_البوت_هنا
TELEGRAM_CHAT_ID=ضع_معرف_المحادثة_هنا
GOOGLE_SHEET_URL=https://script.google.com/macros/s/معرف_النشر/exec
```

ثم شغّل بيئة التطوير:

```bash
vercel dev
```

افتح الرابط المحلي الذي يوفره Vercel، وغالبًا يكون `http://localhost:3000`.

> لا تضع التوكن في `index.html` أو `script.js` أو `products.json`، ولا ترسله إلى مستودع Git.

## إعداد Telegram

1. افتح Telegram وابحث عن `@BotFather`.
2. نفّذ الأمر `/newbot` واتبع التعليمات.
3. احتفظ بالتوكن الذي يعيده BotFather بسرية تامة.
4. أرسل رسالة إلى البوت أو أضفه إلى المجموعة المطلوبة.
5. استخرج `chat ID` بالطريقة المناسبة لحسابك أو مجموعتك.
6. أضف القيمتين إلى متغيرات البيئة في بيئة التشغيل.

تستخدم الدالة الخلفية الملف [api/send-telegram.js](api/send-telegram.js)، وتقبل طلبات `POST` فقط على المسار `/api/send-telegram`. جسم الطلب المتوقع:

```json
{
  "message": "نص الطلب المنسق بصيغة Telegram MarkdownV2"
}
```

## النشر على Vercel

1. ارفع المشروع إلى GitHub أو اربطه مباشرة بحساب Vercel.
2. أنشئ مشروعًا جديدًا في Vercel واختر مستودع المشروع.
3. اترك إعدادات البناء فارغة؛ فهذا مشروع ملفات ثابتة مع Serverless Function.
4. من **Project Settings > Environment Variables** أضف:
   - `TELEGRAM_BOT_TOKEN`
   - `TELEGRAM_CHAT_ID`

- `GOOGLE_SHEET_URL`، وهو رابط Web App المنتهي بـ `/exec`.

5. اختر البيئات المطلوبة: Production وPreview وDevelopment حسب الحاجة.
6. نفّذ Deploy.
7. اختبر الموقع بإضافة منتج وإرسال طلب تجريبي، ثم تحقق من وصول الرسالة إلى Telegram.

### ملاحظة عن `.env.example`

يوجد ملف [.env.example](.env.example) كمرجع. أسماء المتغيرات التي تقرأها الدالة هي `TELEGRAM_BOT_TOKEN` و`TELEGRAM_CHAT_ID` و`GOOGLE_SHEET_URL` مباشرة. عند التشغيل المحلي استخدم ملف `.env` بهذه الأسماء دون بادئة `ENV.`، وتأكد من عدم نشر الملف أو قيمه السرية.

## إدارة المنتجات

تُدار المنتجات من الملف [products.json](products.json). كل عنصر يجب أن يحتوي على الحقول التالية:

| الحقل         | النوع     | الوصف                                               |
| ------------- | --------- | --------------------------------------------------- |
| `id`          | نص أو رقم | معرف فريد للمنتج                                    |
| `category`    | نص        | اسم القسم، ويجب أن يطابق أحد الأقسام في `script.js` |
| `isActive`    | منطقي     | `true` لعرض المنتج و`false` لإخفائه                 |
| `maxQty`      | رقم       | الحد الأقصى للكمية في الطلب                         |
| `name`        | نص        | اسم المنتج                                          |
| `price`       | رقم       | السعر الحالي بالجنيه المصري                         |
| `oldPrice`    | رقم       | السعر السابق الظاهر للمقارنة                        |
| `image`       | نص        | المسار النسبي لصورة المنتج                          |
| `description` | نص        | وصف مختصر يظهر في البطاقة                           |

مثال:

```json
{
  "id": "71",
  "category": "أدوات الرسم",
  "isActive": true,
  "maxQty": 6,
  "name": "اسم المنتج",
  "price": 10,
  "oldPrice": 12,
  "image": "./image/أدوات الرسم/اسم المنتج.webp",
  "description": "وصف مختصر للمنتج."
}
```

عند إضافة صورة جديدة، احفظها داخل مجلد الصور المناسب وتأكد من تطابق الاسم والمسار مع قيمة `image`. إذا تعذر تحميل الصورة، تعرض الواجهة صورة بديلة تلقائيًا.

### تعديل الأقسام

أسماء الأقسام المعروضة في القائمة موجودة في مصفوفة `categories` داخل [script.js](script.js). عند إنشاء قسم جديد، أضف الاسم نفسه إلى المصفوفة وإلى قيمة `category` في المنتجات التابعة له.

### تعديل رسوم التوصيل

غيّر الثابت `DELIVERY_FEE` داخل [script.js](script.js). ويجب أيضًا مراجعة النص الظاهر في [index.html](index.html) إذا تغيرت قيمة الرسوم، حتى تبقى الواجهة والعملية الحسابية متطابقتين.

## طريقة استخدام العميل

1. يفتح العميل الموقع ويختار القسم من زر القائمة.
2. يحدد الكميات باستخدام زري `+` و`-`.
3. يراجع المنتجات والإجمالي في ملخص الطلب.
4. يملأ الاسم ورقم الهاتف والعنوان، ويمكنه إضافة ملاحظات اختيارية.
5. يضغط **تأكيد وإرسال الطلب**.
6. عند النجاح، تظهر رسالة تحتوي على رقم الطلب، وتصل التفاصيل إلى Telegram.

لا يمكن إرسال الطلب دون اختيار منتج واحد على الأقل أو إدخال بيانات التوصيل المطلوبة ورقم هاتف صحيح.

## ملاحظات مهمة

- السلة مؤقتة داخل الذاكرة؛ إعادة تحميل الصفحة تمسح المنتجات المحددة.
- رقم الطلب عشوائي من أربعة أرقام، وليس معرفًا فريدًا مضمونًا على مستوى قاعدة بيانات.
- لا توجد قاعدة بيانات أو نظام مخزون؛ `maxQty` حد واجهة فقط وليس تحققًا من المخزون الفعلي.
- الرسوم الحالية تُضاف حتى عندما تكون السلة فارغة في الملخص، لكن لا يمكن إرسال طلب فارغ.
- البيانات الشخصية تُرسل إلى Telegram؛ يجب إبلاغ العملاء بذلك والالتزام بسياسة الخصوصية المعمول بها.
- يعتمد الموقع على خدمات خارجية عبر CDN وGoogle Maps وGoogle Fonts وFont Awesome، لذلك قد تتأثر بعض العناصر عند حجب هذه الخدمات.
- استخدم HTTPS عند النشر، ولا تسجل محتوى الطلب أو متغيرات البيئة في سجلات عامة.

## استكشاف الأخطاء

### تظهر رسالة «تعذر تحميل المنتجات»

- تأكد من تشغيل الموقع عبر خادم HTTP بدل فتح الملف مباشرة.
- تحقق من وجود [products.json](products.json) في جذر المشروع.
- تأكد من أن الملف JSON صالح ومصفوفة، وأن مسارات الصور صحيحة.
- راجع Console في أدوات المطور لمعرفة الخطأ.

### لا يصل الطلب إلى Telegram

- تأكد من وجود `TELEGRAM_BOT_TOKEN` و`TELEGRAM_CHAT_ID` و`GOOGLE_SHEET_URL` في بيئة Vercel.
- أعد النشر بعد تعديل متغيرات البيئة.
- تأكد من أن البوت يستطيع إرسال الرسائل إلى المحادثة أو المجموعة.
- راجع سجل الدالة في Vercel، ثم اختبر المسار من خلال إرسال طلب تجريبي من الموقع.

### يعمل الموقع لكن الإرسال يفشل محليًا

- شغّل المشروع باستخدام `vercel dev` بدل خادم ملفات ثابت فقط.
- تأكد من أن الطلب يرسل إلى `/api/send-telegram` من نفس المضيف.
- لا تستخدم أسماء المتغيرات `ENV.TELEGRAM_BOT_TOKEN` أو `ENV.TELEGRAM_CHAT_ID`؛ استخدم الأسماء التي تقرؤها الدالة مباشرة.

## الترخيص والملكية

هذا المشروع مخصص لمتجر بيعلي جملة. لا تُعدّل بيانات المنتجات أو الهوية البصرية أو روابط التواصل في بيئة الإنتاج دون موافقة صاحب المتجر.
